# 实验协议

状态：预定实验设计，尚无结果。完整数学定义与工程约束以 [plan.md](../plan.md) 为准。

## 对照矩阵

| method_id | 设置 | 回答的问题 |
|---|---|---|
| `initial` | 同一初始学生 | 起点 |
| `rl` | 原 RL 的文本与连续动作更新 | 任务奖励对照 |
| `opd_text` | 只蒸馏文本和粗框文本 | 排除语言部分带来的收益 |
| `opd_coord` | 只蒸馏连续动作分布 | 连续头独立收益 |
| `opd_joint` | 文本＋连续动作分布蒸馏 | 联合方法 |
| `opd_hybrid` | joint OPD 加任务奖励 | pilot 后可选 |

先做 1,000—3,000 条训练样本的 pilot；开发集约 300 条只是建议规模，按实际可用数据调整并固定。正式结论至少 3 个种子。不要把原始完整数据和模型文件上传 GitHub。

## 公平性与数据

- 固定学生初始化、可训练参数范围、分辨率、调用上限和解码协议。LoRA 与全参训练分开报告。
- teacher 选择和超参数只使用开发集；官方测试集不用于调参或诊断筛选。
- 同样本预算和同 GPU 成本分别比较；多 rollout、teacher 评分、judge 和教师准备成本都要报告。
- 混合 GPU 的小时数按型号分别记，不将 A800 小时与 L20 小时当成等价算力直接比较。
- 不同方法在同一组样本上做 paired bootstrap；按原图或根任务重采样，不以 token 或子调用充当独立样本。

## 指标

主指标：任务准确率、匹配预算的收益、训练成本和推理总时延/生成 token/工具次数。

本项目诊断指标：有效框率、最终 crop 的证据覆盖、框面积、粗框到细化框的变化；仅在有标注子集上算 IoU。分清 raw KL 与有效区域一致性。

准确率统一记录为 0—1；没有测量的数据留空，不能以 0 代替。异常、OOM、超时和协议失败同时报告，不能悄悄剔除使准确率变高。

## 每次实验必须保存

1. 从 [experiment.template.json](../configs/experiment.template.json) 复制出本次 manifest，填写模型与数据 revision、Git commit、方法、种子、硬件和训练配置。
2. 记录真实执行命令、参数、时间、日志位置、峰值显存、失败计数和 checkpoint 标识。
3. 在 [metrics.csv](../results/metrics.csv) 中写汇总；表内一行对应一个方法、种子和评测集合。
4. 报告失败实验及中止原因。推断出来的成本标为估算，不能填成已发生账单。

## 小样本决策

先测约 20 次更新的显存和耗时，再决定是否完成 pilot。若只有 KL 下降而任务或效率无改善，先排查 teacher、mask、状态和协议，再决定是否扩展。扩大到多种子和租卡前应有明确的对照信号或可重复的机制问题。

当前不预设可发表结论，也不以单个最高分 seed 代替整体结果。
