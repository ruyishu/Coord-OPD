# 首个开发任务

目标：确认真正被 train.py 调用的动作头、粗框/raw action/final box 变换和 checkpoint，重放 32 条裁剪轨迹，检查 2B 适配条件。

## M0：核查并固定真实输入

1. 阅读 [plan.md](../plan.md) 和 [UPSTREAM.md](../UPSTREAM.md)，记录实际采用的上游提交与入口。
2. 记录 GPU 型号、显存、软件版本、teacher/student checkpoint、tokenizer/processor 和数据来源。缺少权重或 GPU 时继续源码和数据核查，将未实测项写明。
3. 必须同时具有可评分的 VLM 与训练有效的连续头；同架构强 checkpoint 优先，缺少连续头时先建立 teacher。
4. 核验 DeepEyes-Datasets-47k 的训练部分，按原图去重划分；V* Bench 留作外部评测。没有可信 bbox 标签时不报告伪造的 IoU。
5. 将结论写入本目录的新报告 `m0_report.md`；文档中标注“源码确认”“已运行验证”“待验证”，并附对应证据。

硬件清点命令（在 GPU 机器运行）：

```bash
nvidia-smi --query-gpu=name,memory.total,memory.free --format=csv
```

`--query-gpu` 指定型号、总显存和空闲显存，`--format=csv` 便于记录。若在 Codex 提示符手动执行，命令前加 `!`。不要从卡的名称推断具体可用显存。

## M1：32 条真实轨迹

- 从训练数据选固定 32 条调试样本，记录 ID 与选择规则。
- 单图、最多 2 次裁剪；第一版保留上游实际使用的“粗框文本＋连续残差”。
- 保存实际输入、生成 tokens、工具请求和结果、策略版本、失败状态；大图与完整轨迹存外部目录。
- 在 `m1_report.md` 放至少 1 条成功与 1 条失败案例的可核查描述；若未出现某类案例，照实记录。
- 先证明学生能执行工具和读取真实返回值，不用 mock 输出冒充真实 rollout。

需要重点核对：

- [ ] teacher 条件使用学生粗框，而非 teacher 自己的粗框。
- [ ] KL 在变换前 raw action 分布上计算，不能将截断/排序后的像素框代入原高斯。
- [ ] 无动作 batch、奖励相同 batch 可正确处理；teacher 连续头冻结，学生目标参数有梯度。
